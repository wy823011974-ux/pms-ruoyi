# ADR-0002: 调查数据采用 JSON 列存储

**日期**: 2026-05-27  
**状态**: 已采纳

## 背景

不同项目类型、文件类型的Excel列结构完全不同（15~137列不等），无法用固定列的关系表存储。

## 决策

调查数据使用 `pms_survey_data.row_data` JSON 列存储每一行的完整数据，同时冗余存储项目元数据（项目编号、年份、地区、类型名）用于分类查询。

## 理由

1. MySQL 8.0 原生支持 JSON 类型，可以创建虚拟列索引
2. 避免为每种文件类型创建单独的表
3. 冗余元数据避免查询时 JOIN 多表
4. 脱敏后的数据直接存为JSON，无需反序列化

## 后果

- JSON 列查询性能不如结构化列，但冗余元数据可满足大部分筛选需求
- 数据完整性依赖应用层校验，数据库层无法约束JSON内部字段
